# dnstap

`dnstap` is a Rust library for sending structured DNS events to a
[dnstap](https://dnstap.info/) consumer.
It serializes Protocol Buffer dnstap messages and delivers them over the
[Frame Streams](https://farsightsec.github.io/fstrm/) protocol through a UNIX domain socket.

The crate is a sender, not a dnstap collector or decoder.
It owns a background writer thread that queues messages, connects to the configured socket,
and reconnects automatically when the consumer is temporarily unavailable.

## Requirements

- A supported UNIX-like platform.
  The writer uses UNIX domain sockets.
- A current stable Rust toolchain with Cargo.
- A dnstap consumer listening on a UNIX socket, such as a compatible DNS logging service.

No standalone `protoc` installation is required.
The Protocol Buffer bindings are generated by the crate's build script using the pure Rust code generator.

## Add the dependency

Add the crate to your application's `Cargo.toml`:

```toml
[dependencies]
dnstap = "0.1.8"
```

Or use Cargo:

```sh
cargo add dnstap
```

## Send DNS events

Configure the writer with the path to the consumer's UNIX socket, start it, and retain a
[`Sender`](https://docs.rs/dnstap/latest/dnstap/struct.Sender.html) wherever DNS events are produced.
`Sender` is cloneable and can be shared across threads.

```rust
use dnstap::{AuthQuery, DNSTapBuilder, DNSTapWriter, DNSMessage, Sender, SocketProtocol};
use std::net::IpAddr;
use std::sync::mpsc::TrySendError;
use std::time::Duration;

struct DnstapLogger {
    _writer: DNSTapWriter,
    sender: Sender,
}

impl DnstapLogger {
    fn new(socket_path: &str) -> Result<Self, String> {
        let writer = DNSTapBuilder::default()
            .unix_socket_path(socket_path)
            .listen()
            .map_err(str::to_owned)?
            .start()
            .map_err(|error| error.to_string())?;
        let sender = writer.sender();

        Ok(Self {
            _writer: writer,
            sender,
        })
    }

    fn send_auth_query(&self, dns_query_bytes: Vec<u8>) -> Result<(), TrySendError<DNSMessage>> {
        let query = AuthQuery {
            identity: Some(b"authoritative-1".to_vec()),
            version: None,
            socket_protocol: SocketProtocol::UDP,
            query_address: "192.0.2.50".parse::<IpAddr>().unwrap(),
            query_port: 53000,
            query_time: Duration::from_secs(1_700_000_000),
            query_packet: dns_query_bytes,
        };

        self.sender.send(query.into())
    }
}
```

Create `DnstapLogger` once during application startup and retain it for the lifetime of the service.
Pass the original DNS packet in wire format as `dns_query_bytes`.

`Sender::send` is non-blocking.
Handle its `TrySendError` result according to your logging policy: a full queue means the
configured backlog has been reached, while a disconnected queue means the writer has stopped.

### Queue capacity and connection behavior

The default message backlog is 4,096 events.
Set a capacity appropriate for the expected burst size and memory budget:

```rust
let pending_writer = DNSTapBuilder::default()
    .backlog(16_384)
    .unix_socket_path("/run/dnstap.sock")
    .listen()
    .expect("create dnstap writer");
```

Creating and starting the writer does not require the socket consumer to be available already.
The background thread keeps retrying the connection while preserving events that remain in its bounded queue.

## Event types

For common event types, construct one of the provided typed values and convert it into a
`DNSMessage` with `.into()`:

| Helper type | dnstap event type |
| --- | --- |
| `AuthQuery` | `AUTH_QUERY` |
| `AuthResponse` | `AUTH_RESPONSE` |
| `ResolverQuery` | `RESOLVER_QUERY` |
| `ResolverResponse` | `RESOLVER_RESPONSE` |
| `ClientQuery` | `CLIENT_QUERY` |
| `ClientResponse` | `CLIENT_RESPONSE` |

For the remaining dnstap message types, or when fields need to be optional, create a
[`DNSMessage`](https://docs.rs/dnstap/latest/dnstap/struct.DNSMessage.html) directly and select a
[`MessageType`](https://docs.rs/dnstap/latest/dnstap/enum.MessageType.html).
Addresses supplied in `query_address` or `response_address` determine the socket family automatically.

## Development

Build and run the test suite with:

```sh
cargo test
```

The build script regenerates `src/dnstap_pb.rs` from `src/dnstap_pb.proto`.
Commit the generated binding when the schema changes.
